# Implementation plans

Read [planning guidance](../AGENTS.md) and [root guidance](../../../AGENTS.md).

- Name exact files, interfaces, dependency order, tests, and expected verification results.
- Each task should deliver an independently reviewable result; fold test setup into the task that needs it.
- Plans describe future changes. Do not mark commands passed or features implemented before execution.
- Preserve the user's teaching checkpoints and require review of the plan before feature implementation.
- Self-review coverage, interface consistency, failure cases, and plan size before handoff.
- Do not replace the product brief or silently broaden the milestone through a plan.
